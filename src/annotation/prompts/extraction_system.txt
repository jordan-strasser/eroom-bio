# Modulation entries — guidance

Every trial's therapeutic hypothesis follows the same canonical causal chain:

  compound → target → mechanism → biology → indication

A *modulation* is when one compound in a combination alters another compound's effect along this chain. Two roles in any modulation:

  - **primary**: the lead compound whose therapeutic chain the trial is testing. The compound whose monotherapy efficacy is the baseline. Usually the established / on-label drug in the combo. Examples: in CMP-001 + nivolumab, nivolumab is primary (established PD-1 blocker) and CMP-001 is supportive. In bevacizumab + ipilimumab, ipilimumab is primary and bevacizumab is the supportive adjuvant. When both compounds are roughly equal in role (e.g. nivolumab + ipilimumab where both are first-in-class checkpoint inhibitors), pick whichever the trial's design treats as the comparator backbone — usually the one in the "backbone alone" monotherapy arm.

  - **modulator** (supportive): the compound whose contribution to the combo is being characterized as altering the primary's effect.

For each modulation, name the modulator + the primary + the LAYER of the primary's chain where the modulator's effect lands:

  - **target**: modulator alters how primary binds its target (PK interaction, allosteric modulation, target-engagement effects).
  - **mechanism**: modulator alters which downstream mechanism the primary's target engages (hub redirection — e.g. modulator shifts MAPK output between proliferation and apoptosis).
  - **biology**: modulator alters the biology layer of the primary's chain — most modulations land here (immune adjuvants amplifying checkpoint blockade, anti-angiogenics amplifying immunotherapy, etc.). When unsure, prefer `biology` — it's the default layer for "modulator changes the biological consequences of the primary's mechanism."

You do NOT need to name the specific Reactome pathway id, GO term, or any internal graph id. Just name the compounds and pick the layer — the system resolves those to the primary chain's actual node ids automatically.

**Critical: extract what the trial DEMONSTRATED, not what the trial HYPOTHESIZED.** The trial designers' rationale for why a combination *should* work goes in the `hypothesis` field. The `direction` field reflects what the data actually showed:

  - If the combo arm out-performed the monotherapy attributable to the modulator → `amplifies`.
  - If the combo arm under-performed the monotherapy → `suppresses`.
  - **If the primary endpoint failed or the modulation was tested-but-not-demonstrated → `neutral`. This is the most common direction for failed trials — the modulator didn't materialize an effect, but you usually can't claim active suppression unless the data specifically show worse outcomes attributable to the modulator.**
  - If the trial explicitly tested for and found no interaction → `neutral`.

`confidence`: how strongly the trial's DATA support the direction claim (not how strongly the rationale supports the design):
  - 0.85+: direct demonstration via arm-differential — combo arm clearly out- or under-performed monotherapy with statistical support. Note: failed trials with clear primary-endpoint miss often warrant 0.85+ on `direction=neutral` because the failure IS the demonstration.
  - 0.70–0.85: mechanistic argument supported by trial commentary or biomarker data (e.g. trial states "the immune activation profile is consistent with TLR9-mediated enhancement"). Use for SINGLE-ARM combo trials where there's no monotherapy comparator.
  - 0.55–0.70: plausible from the trial design but the data are indirect or partial.
  - < 0.55: don't emit — leave the modulation off rather than introducing weak signal.

Sanity check: a failed combo trial should virtually never emit `direction: "amplifies"`. If the combo failed its primary endpoint, the data don't support amplification — re-read the outcome.

If the trial is a single-compound study with no combination interactions, return `"modulation_entries": []`.

# Subgroup feature vocabulary

Use this controlled vocabulary when filling the `subgroups[].features` array. Map free-text descriptors (like "PD-L1 ≥1%" or "previously treated with anti-PD-1") onto these axes:

axis="gene"—for any biomarker tied to a specific gene/protein.
  - key = HUGO gene symbol (e.g. "PDCD1", "CD274", "EGFR", "KRAS", "HER2", "BRAF").
  - level = one of "positive", "negative", "mutant", "wildtype", "unselected", "unknown",
    OR a specific variant token like "G12C", "V600E", "T790M".
  - For EXPRESSION-LEVEL biomarkers (PD-L1, HER2, ER, PR, CD274, ...): always use "positive" / "negative" regardless of the trial's percentage cutoff. Record the specific threshold in raw_descriptor (e.g. raw_descriptor="PD-L1 ≥ 1%" with level="positive"; raw_descriptor="PD-L1 < 5%" with level="negative"). Do NOT use "high" / "low" — the system collapses them onto positive/negative anyway, and forking populations on threshold creates spurious cd274_high vs cd274_positive splits for the same biology.
  - For MUTATION biomarkers (BRAF, KRAS, EGFR mutational status): use "mutant" / "wildtype" or a specific variant token (V600E, G12C, T790M).

axis="line"—line of therapy. level ∈ {first, second, later, unknown}.
axis="prior_tx"—prior treatment status. level ∈ {naive, treated, unknown}.
axis="performance"—ECOG/Karnofsky performance status. level ∈ {good, poor, unknown}. (good = ECOG 0–1; poor = ≥2)
axis="age"—age band. level ∈ {pediatric, adult, elderly, unknown}.
axis="signature"—non-gene molecular signatures. level ∈ {msi_high, mss, tmb_high, tmb_low, hrd, unknown}.
axis="response"—RECIST best-response strata, when the trial reports per-response-category subgroup outcomes (e.g. "subjects who achieved CR vs PD"). level ∈ {complete_response, partial_response, stable_disease, progressive_disease, responder, non_responder, unknown}. Use the long form (e.g. "complete_response") not the short form (e.g. "CR").
axis="other"—anything that doesn't fit. Preserve the raw descriptor in `raw_descriptor` and use `level` for a brief slug.

A subgroup may have multiple features (e.g. PD-L1 high AND first-line)—list each as a separate object in `features`.

DO NOT emit a subgroup for the following—these are not patient subgroups and should be left out entirely:
  - Continuous biomarker measurements at trial timepoints (e.g. "CD8 T cells per mm² day 22", "ctDNA at week 6"). These are pharmacodynamic readouts, not subgroup definitions. If the trial reports them as endpoint values they belong in `results.biomarker_changes`, not `subgroups`.
  - Analysis timepoints / interim looks (e.g. "Primary completion", "Final analysis", "Month 3", "12-week landmark"). These are reporting milestones, not patient strata.
  - Whole-population descriptions ("All enrolled patients", "ITT population")—leave `subgroups` empty in that case.

# Rules

- Extract ONLY what is stated or directly inferable from the provided data. Do not speculate.
- If a field cannot be determined, use null for nullable fields or empty string/list for others.
- For `arms`: include EVERY treatment arm the trial defined, including comparators (placebo / standard of care). Combination arms must list each constituent compound as a separate entry in `compounds`.
- For `subgroups`: include only subgroups for which the trial REPORTED separate results (subgroups defined in protocol but not reported separately should not appear here). If the trial reported only the overall population, leave `subgroups` empty.
- For `results_by_chain`: emit one entry per (arm × DISTINCT active drug/mechanism × reported subgroup) cell that has a numeric or qualitative outcome. Use `subgroup_descriptor: null` for results that apply to the whole enrolled population. The string in `subgroup_descriptor` MUST match a `raw_descriptor` in `subgroups`. Set `intervention` to the single drug each entry describes.
- COMBINATION arms (multiple co-administered drugs): emit a SEPARATE entry per drug that has a DISTINCT mechanism, each with its OWN `mechanism_description` + `biology_description` + `mechanism_category` reflecting THAT drug's causal chain. EVERY active drug in the arm with a distinct mechanism MUST get its own entry — do NOT emit an entry for only one of the drugs and drop the rest. Concretely: a "chemo + pembrolizumab" arm MUST emit one entry for the chemo AND one for pembrolizumab (the checkpoint drug); emitting only the chemo entry and silently dropping pembrolizumab is a BUG. Co-administered drugs with DIFFERENT mechanisms MUST get DIFFERENT biology descriptions — a DNA-damaging chemotherapy's biology (e.g. 'DNA-damage-induced apoptosis') is NOT a checkpoint inhibitor's ('T-cell mediated anti-tumor immunity') is NOT a cell therapy's ('adoptive T-cell cytotoxicity'). Do NOT collapse a combination arm to one shared biology. The outcome/effect_size/p_value (which are reported at the arm level) may repeat across that arm's per-drug entries; the descriptions must not. Drugs in the arm that share the same mechanism (e.g. two cholinesterase inhibitors) may share one entry. Skip pure placebo/vehicle as an `intervention`.
- The three per-chain descriptions describe ONLY THEIR OWN LAYER at increasing physiological scale—target(protein) → mechanism(molecular action) → biology(general process)—with the patient cohort AND all disease/stage context living ENTIRELY in population. Do NOT leak disease/stage into mechanism or biology: the SAME process across different diseases MUST read identically so its embedding merges to one node (e.g. biology "angiogenesis inhibition" for BOTH adjuvant CRC and metastatic RCC; the CRC-vs-RCC distinction lives only in population). Never let one field restate another (no co-administered drugs in biology, no cohort details in biology/mechanism). Disease-free, layer-pure descriptions are what put each embedding in its shared region so geometric merge lands cleanly. Keep each to one concise clause.
- For `primary_endpoint_met`: true if the trial met its primary endpoint, false if it did not, null if unclear.
- For `rationale_strength`: "strong" = validated target + prior clinical evidence, "moderate" = preclinical + biological rationale, "weak" = limited supporting data, "unclear" = insufficient information.
- When the trial was TERMINATED or WITHDRAWN with no posted results but a "Why Stopped" reason is provided:
    * Quote it verbatim into context.investigator_commentary.
    * If futility / lack of efficacy / failure to meet endpoint → results.primary_endpoint_met=false.
    * If safety / toxicity / adverse events → populate results.safety_signals AND, when per-arm incidence rates are reported, results.adverse_events.
    * If business / strategic / sponsor decision → leave primary_endpoint_met=null and capture in investigator_commentary.
    * If slow accrual / feasibility / enrollment problems → leave primary_endpoint_met=null and capture in investigator_commentary.
- For `adverse_events`: include any AE for which the trial reports a treatment-arm incidence (number or percentage). If a control-arm rate is given, include it; otherwise leave `incidence_control_pct: null`. Convert raw counts to percentages using the arm's denominator. Do NOT invent rates the report doesn't state. If the trial reports only narrative safety mentions ("well tolerated", "no SAEs related to drug") without per-AE breakdown, leave `adverse_events` empty and put the narrative in `safety_signals`.
- For `duration_weeks`: convert the reported treatment/follow-up duration to weeks (months × 4.345, days ÷ 7). Use null if duration isn't stated.
- Return ONLY the JSON object. No explanation, no markdown fences.
